Your turn: three drills

Do these alone. They live in drills/lesson-1/ and both coded drills start RED; sh drills/lesson-1/check.sh shows your progress.

D1 · Extend a type, end to end. Give a workspace an optional description (at most 500 characters, no control characters, trimmed). You will touch the contract, a new migration, the db layer, and possibly the route. make check must stay green: the gate applies to you too.

Predict first: which of the four layers needs no change, and why? (Section 5 has the answer.)

D2 · Fix a planted bug. drills/lesson-1/d2-cursor/cursor.ts is a simplified copy of the paging code with one bug. Its test walks five rows created in the same millisecond and expects each exactly once. Form a theory before you read section 4's case study again.

D3 · Explain a decision before reading mine. Answer out loud or on paper, then open the answer.

1. Why does createDb return an object of closures instead of a class with a private field?

TypeScript's private is erased at runtime, so it is a note to the compiler, not a wall. A closure variable is unreachable by anything: no reflection, no subclass, no this to lose when a method is passed as a callback. The tenancy rule is too important for a convention.

2. Why is a non-member answered with 404 rather than 403?

403 confirms the org exists. "Not a member" and "no such org" are resolved by one query and return byte-identical responses, so the API never tells a caller anything about a tenant they do not belong to.

3. The session token names user, org and document. Why not the role too?

A token is checked once, when the socket opens; the socket then lives for hours. A role baked into it would stay whatever it was at connect time, and epic 8 requires a role change to reach open sessions within ten seconds. The sync server must read the role itself and be pushed changes.

Recall first

Look away. Trace POST /orgs/:orgId/workspaces through its five steps, and name the three layers that enforce tenancy. Then check.

Check yourself

Identity middleware (401) → org middleware: member? (404) → body parsed against the contract (400 naming the field) → db.forOrg(orgId), the only door → Postgres constraints. Tenancy is enforced by the closure (no unscoped query can be written), a compile-time @ts-expect-error test (a new door fails the build), and the composite foreign key (the database refuses).

Then test it

Eight questions. Options are shuffled each visit.

1. export const Org = z.object({...}) and export type Org = z.infer<typeof Org> in one file. Why is that not a name clash?

Org.parse(x) uses the value; const o: Org uses the type. The compiler always knows which position it is in.

2. The contract trims a name then requires length ≥ 1. The database only requires length ≥ 1. A client sends three spaces. What happened in the first version?

Validation ran only on the read side. The row was storable but unreadable. Parse inputs with the same contract before writing.

3. What does // @ts-expect-error above void db.pool; prove?

Unlike @ts-ignore, it is an assertion: no error on the next line is itself an error (TS2578). A compile-time test.

4. Why does the paging cursor carry the timestamp as Postgres text instead of going through a JavaScript Date?

Rows created in the same millisecond would be skipped or repeated. That is Drill 2.

5. A handler writes const { name } = await body(c, CreateOrgBody). Where does name's type come from?

body<S extends z.ZodType>(c, schema: S): Promise<z.infer<S>>: the return type is computed from the argument.

6. Auth was first applied to /orgs/* only. What was wrong with that?

Security defaults must fail closed: everything needs a caller except an explicit allowlist.

7. Tests passed noIdentity to startServer and saw 401. Why did that NOT prove production is safe?

An injected dependency proves the dependency, not the wiring. The fix runs the real entry point in a child process with a clean environment.

8. verifySessionToken returns {ok:false, reason} instead of throwing. Why?

TypeScript cannot say what a function throws. A discriminated union puts the failure in the type, where the compiler can see it.
